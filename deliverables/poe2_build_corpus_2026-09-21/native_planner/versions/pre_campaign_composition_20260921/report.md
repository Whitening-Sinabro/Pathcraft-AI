## 남는 지원 한계

- 실제 게임 로드·표시·작동과 1.0.0 호환 생존은 확인하지 않았습니다.
- 메타젬은 공식 미지원입니다. 메타 연결 전체와 장비/전직 부여 스킬은 설명으로 남겼으며 구매 젬으로 변조하지 않았습니다. 그래서 게임 제작 목록 수는 XML 그룹 수보다 적습니다.
- 기본 Mace Strike는 캠페인 설명에만 남깁니다. Ahn's Citadel 등 특수 보조는 ID를 검증했고 빌드 설명에서 별도 확보를 안내합니다. 제작 지원의 상세 한계는 validation.json에 보존했습니다.
- 스킬 무기 세트는 공식 키가 없어 설명으로 보존합니다. 작성자 방패벽1/함성2 권장과 XML global 플래그는 구분했습니다. 패시브 무기 세트는 공식 `weapon_set`으로 직접 보존합니다.
- 독립 Inventories 테이블이 없어 슬롯 ID는 기존 변환기의 매핑을 사용했습니다. 고유명도 Words 테이블 검증 없이 `unique_name`으로 단정하지 않고 슬롯 설명으로 표시했습니다.
- 전환 최소 레벨·캠페인 패시브 클릭 순서는 만들지 않았습니다. 레벨97은 최신 캐릭터의 저장 상태입니다.

남은 사용자 단계는 README를 읽고 선택한 파일을 직접 임포트하여 게임 내 표시와 자원·무기세트를 확인하는 것입니다. 작업 터미널은 사용자 유지 지시에 따라 coordinator의 retain 대상으로 요청했습니다.

## 후속 UX 수정 검수

게임 문구의 `enabled=true`, `set1/set2`, 내부 분류명, PoB 운영 필드를 제거했습니다. 원본 그룹 속성·젬 속성·제외 사유는 `validation.json`에 그대로 보존했습니다. 최신 방패벽은 방어도 방패·젬 요구치 및 세트1, 함성은 세트2와 Eternal Rage·Raging Cry·Enraged Warcry II 확인을 안내합니다. Execute III·Clash는 아홉꼬리 장착 후 저생명력 유지와 플라스크 예외 확인을 안내하며 역사 조건과 구분합니다.

메타·부여 스킬의 중복 자동 그룹은 표시만 합쳤습니다. 빌드 설명의 스킬/보조 목록은 가장 완전한 원본 연결을 보존하며 게임에서 직접 연결하도록 안내합니다. 보조마다 반복하던 플래그·긴 검증 경고도 제거했습니다.

수정 전 `ux_structure_baseline.json`과 문구 필드만 제외한 구조를 비교하여 10개 파일명·모든 ID·전직·151노드 세트 분리·장비 슬롯이 변경되지 않았음을 확인했습니다. 재생성 시 공식 키/형식·BaseItemTypes/SkillGems·원본 해시·HTML 공통팩 대조를 다시 통과했습니다. 게임 설치와 실행은 하지 않았습니다.
