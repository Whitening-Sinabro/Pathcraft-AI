# 탱정 키타바 — 게임용 빌드 플래너

게임용 JSON `.build`와 한국어 단계 조건입니다. HTML 안내는 옆 `../planner/` 폴더에서 함께 보세요. **현재 저자본 기준은 `current-kitava-29d39.build`입니다.** `archive-*` 4개는 당시 구성 비교용이며 순서대로 따라야 하는 필수 전환 단계가 아닙니다.

## 파일 선택과 조건

|---|---|---|

90·91·93·94·97은 저장된 캐릭터 레벨입니다. 최소 전환 레벨이나 안전한 콘텐츠 진입 레벨이 아닙니다. 파일의 젬 레벨도 원본 관측값입니다. 단계별 최소 레벨의 근거가 없어 `level_interval`을 임의로 생성하지 않았습니다.

캠페인 참조는 별이슬골짜기 0.5 및 0.5.5 가이드에서 확인된 스킬만 안내합니다. 원본 Warbringer/Titan 패시브와 전직은 옮기지 않았고 키타바 캠페인 패시브 클릭 순서를 만들지 않았습니다. 실제 탱정 키타바 전직·목표 트리는 최신 파일에서 별도로 확인하세요. 탱정 보정은 액트2 묻힌 성소에서 불 선택, 액트4 번개 골렘 다음 화염 골렘 경로입니다. 확인된 근거와 적용 범위는 `../priority_taengjeong_kitava_shield_wall.md`에 있습니다.

## 최신 저자본을 사용할 때

- 아홉꼬리의 원문은 **플라스크 이외 회복**이 저생명력 위로 회복하지 못한다는 조건입니다. 플라스크는 예외이며 저생명력이 항상 자동 유지된다고 보장하지 않습니다.
- Eternal Rage 활성과 Infernal Cry의 Raging Cry·Enraged Warcry II 조합을 확인하세요. 작성자는 방패벽 세트1 / 함성 세트2를 권장합니다. XML `enableGlobal1/2` 값은 별도로 보존했고 이 권장 배정과 동일하다고 주장하지 않습니다.
- Atziri's Communion은 과거 안내의 **보조젬**입니다. 최신 29d39에는 없고 필수 장비나 유일한 저생명력 조건으로 넣지 않았습니다.
- 황동철갑 등으로 전환할 때 일반 갑옷 전제 전직을 그대로 유지하지 않습니다. Constricting Command 이전에 관련 포위 노드를 먼저 찍지 않습니다.
- 원본 장비는 관측 예시입니다. 모든 희귀 옵션·특수 보조·고유 장비를 캠페인 구매 필수품으로 보지 마세요.

## 임포트

1. 사용할 `.build` 파일을 선택합니다. 과거 기록은 비교할 때만 선택하세요.
2. [공식 빌드 플래너 안내](https://www.pathofexile.com/developer/docs/game#buildplanner)에 따라 웹사이트에 업로드하거나, Windows의 `문서/My Games/Path of Exile 2/BuildPlanner` 폴더에 선택한 파일을 **직접** 복사합니다. 문서 폴더 위치가 변경된 PC는 실제 게임 문서 폴더를 확인하세요.
3. 게임에서 해당 빌드를 선택하고 스킬·전직·패시브 및 장비 슬롯 안내가 표시되는지 확인합니다. 표시되지 않으면 게임의 현재 포맷 지원을 확인하세요. 이번 납품에서는 게임 폴더 설치나 게임 실행을 하지 않았습니다.
4. 게임에서 스킬별 무기 세트와 정신력·자원·능력치 조건을 직접 확인합니다. 파일은 장비 장착이나 스킬 세트 배정을 자동 실행하지 않습니다.

## 포맷상 한계와 검증

[공식 문서](https://www.pathofexile.com/developer/docs/game#buildplanner)를 2026-09-21 직접 확인했습니다. 현재 Build 포맷은 실험적 Version 1이며 메타젬은 미지원입니다. `version`, `class`, 스킬의 `weapon_set` 같은 비공식 키를 추가하지 않았습니다.

Fire Spell on Hit + Detonate Dead, Blasphemy 등 메타젬 연결과 장비/전직 부여 스킬은 빌드 `description`과 주얼·패시브·장비의 `additional_text`에 안내하고 구매 젬으로 바꾸지 않았습니다. 같은 부여 스킬을 수동 그룹과 자동 `source=Item/Tree` 그룹에 중복 기록한 XML도 모두 보고서에 남겼습니다. 원본 `GemType`, 제작 테이블과 `source`를 확인했으며 특수 보조는 일반 미가공 보조젬으로 제작할 수 있다는 보장을 하지 않습니다.

5개 키타바 원본의 숫자 노드 → `stringId` 매핑, 원본 전직 Warrior3, 공통/세트1/세트2 배분, 활성 SkillSet/ItemSet, 모든 젬 ID와 플래그를 검증했습니다. 최신 151개는 시작 노드를 포함한 원본 전체이며 실제 지출 포인트가 151이라는 뜻이 아닙니다. 능력치 선택과 장착 주얼은 패시브 도움말에 보존합니다. 장비 템플릿의 비활성 variant pool은 출력하지 않습니다.

`validation.json`에 입력·출력 SHA-256, 공통 HTML 데이터팩 비교, 원본 스킬 전체, 제외 사유와 지원 한계가 있습니다. 스냅샷 트리 0_5와 PoB targetVersion 0_1을 보존하되 그 숫자로 세부 게임 패치를 확정하지 않습니다. 0.5.5 관련 자료라는 문맥과 최신 9월21일 정정은 함께 보존했습니다. **실제 게임 로드·동작·1.0.0 생존은 미검증**입니다. `Inventories` 원본 테이블은 없어 슬롯 ID는 기존 검증된 변환기의 매핑을 따랐습니다.

`generate.py`는 이번 납품을 재생성하고 정적 검증하는 보조 스크립트입니다. 원본과 공통팩을 읽고 이 폴더에만 씁니다. 기존 설치 기능이 있는 생성 스크립트를 실행하지 않았습니다.

## 게임 안내 문구 정리

게임 툴팁에는 짧은 사용 조건만 표시합니다. `enabled`, `enableGlobal1/2`, 내부 제외 사유와 전체 원본 젬 속성은 `validation.json`에서 확인할 수 있습니다. 최신 Execute III·Clash는 아홉꼬리 장착 후 저생명력 유지 확인, Infernal Cry는 Eternal Rage 활성과 Raging Cry·Enraged Warcry II 연결을 안내합니다. 과거 보관 파일의 조건을 최신 필수 조건으로 가져오지 않았습니다.

지원되지 않는 메타·부여 스킬 연결은 빌드 설명에 정확한 스킬과 보조 이름으로 한 번씩 표시합니다. 게임에서 해당 스킬을 얻은 뒤 직접 연결하세요. `ux_structure_baseline.json`은 문구 수정 전의 파일 구조·ID 비교용 자료이며 게임에 복사하지 않습니다. 10개 파일명, 스킬·보조 ID, 패시브·전직·무기 세트 및 장비 슬롯 구조가 그대로인지 재검사했습니다.
