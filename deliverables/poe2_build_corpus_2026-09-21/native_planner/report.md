공식 [Build Planner 문서](https://www.pathofexile.com/developer/docs/game#buildplanner)의 현행 허용 키·필수 필드·자료형을 직접 확인하여 로컬 검사했습니다. 공식 배포 검증기를 사용했다는 뜻은 아닙니다. JSON 재파싱, 전체 원본 SHA-256, BaseItemTypes/SkillGems ID, 숫자 노드/stringId 및 무기 세트 대응 검사를 통과했습니다. `.//Skill`을 활성 SkillSet 아래에서 탐색했으며 그룹·젬 활성 플래그와 부여 스킬 원본은 보고서에 모두 남겼습니다.

`planner_data/build_data.json`과 5개 스냅샷의 원본 해시, 전직, 전체 패시브 ID, 무기 세트 배분, 그룹 속성, 모든 젬 속성, 활성 슬롯/아이템 ID가 일치했습니다. 캠페인 5개도 같은 팩의 `campaign_stages`에서 확인된 스킬·보조를 가져와 테이블 ID를 독립 검증했습니다. 팩 해시와 상세 비교 결과는 `validation.json`에 있습니다.

이번 후속 작업에서 `python build_planner_data.py`와 `python native_planner/generate.py`의 최초 검증을 통과한 뒤, 새 A2 확인에 따른 패시브 범위 변경을 적용해 각각 한 번 추가 실행했습니다. 최종 생성기는 5개 캠페인의 원본 노드·연결·공통 배분·연결성, 환불/추가의 모든 중간 상태와 13점 연결부, 10개 파일의 키/자료형·젬 ID·JSON 재읽기, 전체 스냅샷 공통팩 대조와 최신 151=104/24/23을 통과했습니다. 자세한 결과는 `validation.json`의 `campaign_graph_checks`, `campaign_stages`, `html_common_pack_comparison`, `ux_correction`에 있습니다.

캠페인 장비는 액트1 양손 철퇴, 액트2 이후 한손 철퇴+방어도 방패로 구분했습니다. 액트1→2는 5개 환불/13개 추가이고 조기 방패 전환을 위한 13점 공통 연결부를 안내합니다. 포인트 부족 시 이전 체크포인트와 호환 무기를 유지하며, 환불 비용·젬·보조·능력치·정신력 확보를 실제 조건으로 남겼습니다. 좌표와 연결은 원본 트리에서 추출해 공통팩 노드 풀을 확장했습니다.

모든 native 스킬·보조·패시브에 `[1,100]` 표시 범위를 추가했습니다. 사용자 B 표시 관측(msg_db4b49567e07), 원본 액트3의 추천 5개 관측(HQ msg_ccc4f724cad0, relay msg_ba97abe53f22), 사용자 A2 패시브 표시 확인(HQ msg_0f2e79de7708, relay msg_ae87d801be97)을 기록합니다. A2 결과를 받은 뒤에만 패시브 범위를 활성화했고 기존 `weapon_set: 0/1/2`는 보존했습니다. 범위 생략이 모든 문제의 원인이라는 결론은 내리지 않으며, 범위는 습득·배분·사용 가능 레벨이나 새 캠페인 실플레이 PASS를 뜻하지 않습니다.

## 남는 지원 한계

- 실제 게임 로드·표시·작동과 1.0.0 호환 생존은 확인하지 않았습니다.
- 메타젬은 공식 미지원입니다. 메타 연결 전체와 장비/전직 부여 스킬은 설명으로 남겼으며 구매 젬으로 변조하지 않았습니다. 그래서 게임 제작 목록 수는 XML 그룹 수보다 적습니다.
- 기본 Mace Strike는 캠페인 설명에만 남깁니다. Ahn's Citadel 등 특수 보조는 ID를 검증했고 빌드 설명에서 별도 확보를 안내합니다. 제작 지원의 상세 한계는 validation.json에 보존했습니다.
- 스킬 무기 세트는 공식 키가 없어 설명으로 보존합니다. 작성자 방패벽1/함성2 권장과 XML global 플래그는 구분했습니다. 패시브 무기 세트는 공식 `weapon_set`으로 직접 보존합니다.
- 독립 Inventories 테이블이 없어 슬롯 ID는 기존 변환기의 매핑을 사용했습니다. 고유명도 Words 테이블 검증 없이 `unique_name`으로 단정하지 않고 슬롯 설명으로 표시했습니다.
- 전환 최소 레벨·저자의 캠페인 클릭 순서는 만들지 않았습니다. Pathcraft의 연결 순서 증거는 저자 기록과 구분합니다. 레벨97은 최신 캐릭터의 저장 상태입니다.
- 새 캠페인의 게임 표시·DPS·HC 생존 검증은 없습니다. A/B 관측은 새 캠페인의 게임 PASS가 아닙니다.

남은 사용자 단계는 README를 읽고 선택한 파일을 직접 임포트하여 게임 내 표시와 자원·무기세트를 확인하는 것입니다. 작업 터미널은 사용자 유지 지시에 따라 coordinator의 retain 대상으로 요청했습니다.

## 후속 UX 수정 검수

게임 문구의 `enabled=true`, `set1/set2`, 내부 분류명, PoB 운영 필드를 제거했습니다. 원본 그룹 속성·젬 속성·제외 사유는 `validation.json`에 그대로 보존했습니다. 최신 방패벽은 방어도 방패·젬 요구치 및 세트1, 함성은 세트2와 Eternal Rage·Raging Cry·Enraged Warcry II 확인을 안내합니다. Execute III·Clash는 아홉꼬리 장착 후 저생명력 유지와 플라스크 예외 확인을 안내하며 역사 조건과 구분합니다.

메타·부여 스킬의 중복 자동 그룹은 표시만 합쳤습니다. 빌드 설명의 스킬/보조 목록은 가장 완전한 원본 연결을 보존하며 게임에서 직접 연결하도록 안내합니다. 보조마다 반복하던 플래그·긴 검증 경고도 제거했습니다.

역사적 `ux_structure_baseline.json`을 그대로 보존하고, 이전 10개 파일·생성기·기준선·보고서·공통팩을 `versions/pre_campaign_composition_20260921/`에 저장했습니다. 엄격한 허용 차이 검사는 스킬/보조/패시브 `[1,100]` 및 승인 후보와 정확히 같은 캠페인 공통 노드만 허용합니다. 그 외 구조는 역사적 기준선과 같아야 하고, 최신/과거 5개 파일은 원래 데이터·도움말을 보존한 채 표시 범위 및 설명만 추가됐는지도 별도로 대조했습니다. 기준선을 덮어쓰거나 검증을 해제하지 않았습니다. 게임 설치와 실행은 하지 않았습니다.
