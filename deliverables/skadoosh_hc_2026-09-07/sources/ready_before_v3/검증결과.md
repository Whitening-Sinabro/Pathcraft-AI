# 수정 배포본 검증 기록

검증 대상은 수정된 **플래너 13개, 필터 3개**다. 초판의 형식 검사만으로 초반 노드 선택까지 확인된 것으로 설명한 것은 잘못이었다. 이번 검사는 원본 일치, 전환 과정, 설치 파일을 별도로 확인한다.

## 이번에 직접 다시 검사한 내용

- 13개 플래너의 네이티브 JSON 구조, Warrior2 전직, 실제 트리에 있는 패시브 ID, 실제 젬 ID, 중복 노드, 스킬/보조의 표시 상한 100을 검사했다.
- 01·02의 기절 축적 우회를 제거했다. 새 01의 10점 근접 경로가 02에, 02가 이번 리그 실제 24레벨 트리인 03에 포함되는 것을 **무기 세트 배정까지 포함해** 확인했다. 두 전환 모두 환불 0개다.
- 실측 03·04·05·06·07·09의 패시브와 세트 배정을 보존된 외부 API와 다시 비교했다. 실제 스킬 그룹은 각 원본의 PoB XML을 따로 풀어 연결 젬까지 비교했다. 6개 모두 일치했다.
- 인접한 12번 전환의 작업 순서를 직렬화된 파일에서 재실행했다. 매 작업 후 공통 트리, 세트 I, 세트 II, 전직이 연결되어 있고 작업 중 점수 한도를 넘지 않으며 마지막에 목표 트리와 같아지는지 확인했다.
- 07→08 순서에서 방어 0~13점만 추가한 14가지 상태에서도 08A로 직접 이동하는 경로를 별도로 계산하고 독립적으로 재실행했다. 미사용 방어 노드를 먼저 찍도록 강제하지 않는다.
- 연결되지 않은 실제 핵심 노드를 일부러 추가한 반례가 검증에서 실패하는 것도 확인했다. ID가 존재한다는 이유만으로 연결 검사가 통과하지 않는다.
- 05→05A는 트리 변경 0개다. 08A→08B는 선대의 유대 1점, 08B→08C는 혈마법 1점만 추가한다. 08B/08C에는 파콰테가 없고 기존 타락시키는 비명 I가 남아 있다.
- 08B/08C의 AWT는 지면 분쇄를 내부에 연결하고 보조 위치 3개를 사용한다. 09는 제작자 직접 내보내기 파일과 같은 AWT 연결 구조, 보조 위치 4개를 보존했다.
- 후기 구성의 불의 순수함 2개와 서로 다른 보조 연결을 보존했다. 두 스킬은 성소 셉터 각각에서 부여되며, 이름이 같아도 합치지 않는다.
- 한국어 젬 이름 52개를 확인한 외부 이름 표를 사용했다. 각 스킬과 연결 보조 이름이 해당 스킬·보조의 네이티브 설명에 모두 있는지 검사했다. 환불 진입 조건은 빌드 설명에, 전체 작업 순서는 동봉 패시브전환.md에 보존했다.
- 게임 폴더에 설치한 13개 플래너와 3개 필터가 배포 파일과 바이트 단위로 같은지 확인했다. 기존의 다른 플래너/필터 8개는 설치 전후 해시가 같다.

## 큰 환불 구간의 조건

| 전환 | 작업 중 일반 총량 | 무기 세트 사용 한도 | 환불 노드 |
|---|---:|---:|---:|
| 05A→06 | 60점 | I 12점 / II 14점 | 16개 |
| 08→08A | 트리 작업 95점 | I·II 각 22점 | 38개 |

08A는 다음 선대의 유대와 혈마법의 각 1점까지 준비하도록 **실제 진입은 일반 총 97점 확보 후**로 안내한다. 05A→06은 완성 후 일반 55점이지만 연결을 유지하는 도중에는 총 60점이 필요하다. 일반 총량은 이미 쓴 점수와 미사용 점수의 합이며, 무기 세트 한도는 별도 퀘스트 획득 여부도 확인해야 한다.

이는 공개 트리 연결과 점수 모델에서 검증한 작업 순서다. 실제 UI에서 환불 버튼을 눌러 본 결과나 플레이 피해량 검증이 아니다. 52~74레벨 사이 제작자가 이 순서로 환불했다는 주장도 아니다.

## 필터의 이전 검사와 이번 확인

필터는 수정하지 않았고 앞서 검사한 버전과 해시가 같다. 당시 각 필터에 220개 대상 베이스 × 120개 상태, **26,400건씩 총 79,200건**을 독립 평가기로 검사했다. 검사 범위에서 알림 회귀 0, 추가 Hide 0이었다. 여러 지역 레벨의 셉터·목걸이·호신부·영혼핵 및 유니크 알림 대조도 통과했다.

기존 평가기가 `GemLevel`, `WaystoneTier`, `Width`, `Height`, `TwiceCorrupted`, `AlwaysShow`, `HasVaalUniqueMod`, `IsVaalUnique`, `BaseEnergyShield`, `BaseEvasion`, `BaseArmour` 등 일부 원본 조건을 모델링하지 않는 한계는 그대로다. 해당 원본 규칙을 보존했으며 모든 게임 필터 조건의 실행을 시뮬레이션했다고 주장하지 않는다.

이전 배포 단계에서 실행한 관련 저장소 테스트는 **87 통과, 1 건너뜀**이었다. 이번에는 저장소 구현과 필터가 바뀌지 않아 그 테스트를 반복하지 않고, 바뀐 플래너의 원본/전환/설치 검사를 실행했다.

## 남은 확인과 재현 자료

- 이전 배포본이 실제 POE2에서 읽힌다는 것은 사용자가 확인했다. 이번 시뮬레이션 수정본의 게임 재로딩은 별도 확인되지 않았다.
- 사용자의 실제 장비·젬 레벨·회복으로 실전 전투를 하지 않았다. 중간 단계의 처치 속도와 생존성을 플레이로 보증하지 않는다.
- 실측 API에는 03 이후 스킬별 G 무기 세트 체크박스가 없다. 안내된 배정은 무기/스킬 요구 조건과 패시브에 근거한 Pathcraft 권장안이다.
- 01·02, 08, 05A·08A·08B·08C는 명시된 재구성/제안이다. 실측 스냅샷과 혼동하지 않도록 플래너 내부에도 출처를 적었다.

상위 배포 폴더에 `smooth_transitions.py`, `partial_transitions_v2.py`, `annotate_revision2.py`, `verify_revision2.py`, `install_revision2.py`, `package_revision2.py`를 보존했다. 검증 결과는 `validation_revision2.json`, 설치 해시는 `installation_revision2.json`, 각 작업은 `transition_operations_v2.json`과 `partial_transitions_v2.json`이다. 원본 JSON·제작자 내보내기·공개 트리·필터는 `sources`에 있다. 보조 스크립트는 이번 결과 생성과 검증에만 사용했다.

**확인된 결과는 외부 원본 대조, 전환 모델, 파일 구조, 한국어 안내, 실제 폴더 설치와 조건부 PoB/자원 계산이다. 이전 배포본 로딩은 사용자 확인이다. 하드코어 생존을 보증하는 완벽한 빌드라고 표현하지 않는다.**

## 시뮬레이션 후 수정

공식 커뮤니티 PoB2 v0.23.1 엔진으로 20개 입력을 계산하고, 별도 사건 모델로 62개 자원 조건을 계산했다. 결과와 한계는 [시뮬레이션결과](시뮬레이션결과.md), 시간별 기록은 [오프라인 그래프](시뮬레이션그래프.html)에 있다. 05A 기본 연결에서 정신력이 부족한 명상 II를 제외했고 나머지 실제 제작자 스냅샷 6개는 보존했다. 02→03의 과잉 제거와 전직 한도 증가가 상쇄된다는 점, 05A/06 및 08B의 마나 플라스크 필요, 함성 유효 레벨 하락, 09의 이동/반복 조건과 추가 생명력 비용 불확실성을 플래너 내부에 반영했다.

`simulation/validation_simulation.json`에 현재 캐릭터 입력 시각, PoB/자원 계산 건수와 결과 해시를 남겼다. 파콰테의 반복 비용과 가시 폭발·요철 지대·선대의 영혼을 포함한 전체 피해 계산은 완료되지 않았다. 현재 조건에서 09 전환을 보류하는 이유다.

## 장비 추천과 읽기 쉬운 설명 수정

장비 칸에 섞여 있던 원본 아이템 수치·환불 작업 목록을 정리했다. 모든 단계에 무기·방패·투구·갑옷·장갑·장화·목걸이·허리띠·양 반지·플라스크·호신부 추천을 넣었다. 빈 보조 무기 칸과 마나 플라스크를 없애는 단계도 구분했다.

13개 플래너 모두 빌드 설명 맨 앞에 **무기 I·II 구성 → 각 세트의 스킬과 전체 연결 젬 → 사용 순서**를 모았다. 무기 칸에는 해당 세트의 전체 연결과 추천 옵션을 함께 넣었고, 나머지 장비 칸은 추천 옵션부터 표시한다. 각 스킬·보조의 개별 연결 안내도 유지했다. 실제 스킬 목록을 공통 입력으로 사용해 전체 안내와 개별 안내가 따로 어긋나지 않게 했다. G의 I·II 체크는 권장 배정이며 직접 설정해야 한다.

GGG 공식 형식의 `description`, 스킬/보조/패시브별 `additional_text`를 사용했다. 일반 장비의 자동 옵션 선택 필드는 없으므로 옵션 우선순위는 장비 칸에 표시한다. [공식 형식](https://www.pathofexile.com/developer/docs/game#buildplanner)

`planner_presenter.py`가 플레이어에게 보이는 설명을 생성한다. `verify_planner_presentation.py`는 수정 전후 패시브·젬 연결·젬 표시 범위·고유 아이템 지정의 동일성, 빠진 장비 부위, 추천 옵션의 위치, 설명 길이와 공식 필드를 검사한다. 이 수정은 표시와 장비 추천 안내이며, 추천 옵션으로 만든 새 가상 장비의 DPS를 계산한 변경은 아니다. 기존 PoB/자원 계산 파일이 그대로인 것도 확인한다. 실제 게임에서 새 설명의 위치·줄바꿈을 확인하는 작업은 별도로 완료하지 않았다.
