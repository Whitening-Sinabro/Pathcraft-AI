> 보내는 쪽: Claude 세션 (2026-09-21) · 받는 쪽: 코덱스 (상용화 가능성 검토 중)
> 목적: 사용자가 이 세션에서 만든 **아틀라스 순서 가이드 페이지**를 보고, 앱(Tauri)에서 같은 방식의 기능을 만들 수 있는지 판단하게 한다.

## 0. 결론 먼저

- 사용자가 원하는 앱 기능: **"PoB/캐릭터 → 아틀라스를 어떤 순서로 찍나"를 지도 위에서 재생해 보여주는 뷰어.** 제품 본질(PoB → 파밍·아틀라스·제작 계획)의 아틀라스 축이다.
- 동작하는 레퍼런스가 있다: `deliverables/atlas_viewer_reference_2026-09-21/pages/hc_atlas_order.html` (브라우저로 바로 열림, 외부 의존 없음).
- **상용화 관점의 가장 큰 위험은 기능이 아니라 데이터 출처다.** 이 레퍼런스의 트리 레이아웃은 poe.ninja 의 프론트엔드 번들 JS 에서, 크리에이터 트리는 모발리틱스 페이지 상태에서 긁어 왔다. 상용 앱에 그대로 쓸 수 없다고 가정하고 판단해 달라(§4).

## 2. 앱으로 가져갈 UX 패턴 (사용자가 직접 요구한 것)

사용자 피드백으로 세 번 고쳐서 나온 형태다. 앞의 두 형태는 거절됐다.

1. **거절**: 흑백 + 모양으로 위험도 구분 → "잘 모르겠음"
2. **거절**: 5색을 한꺼번에 칠함 → "알록달록 헷갈려, 사용자 고려 안 하니?"
3. **채택**:
   - 단계 칩(초록 1~58 · 파랑 59~205 · 노랑 206~265 · 주황 266~299 · 빨강 300~336) — **누르면 그 단계만 켜지고 나머지는 흐리게**
   - **앞 단계에서 이미 찍은 노드는 흰색** — "어디서 이어가는지"가 보이게
   - 켜진 노드에 **순번 숫자**, 지금 찍을 노드에 **커서 링**
   - **▶ 재생 / ▶▶ 처음부터 전부**: 시작점부터 노드가 하나씩 튀어오르며 켜짐. 사용자 표현 "팍팍팍팍"
   - 순서는 같은 등급이면 **방금 찍은 노드 옆 → 가까운 노드** 순이어야 한다(아니면 지도에서 여기저기 튄다는 지적)
   - 아래 목록 표 — 행 클릭 = 그 노드로 이동
   - `prefers-reduced-motion` 이면 튀는 효과 끔

## 3. 계산 로직 (재현용)

- **위험도 분류** (`classify.py`, 서브트리는 `full_order.py`): 노드 stat id 정규식으로 위험(몬스터 속성·효과 강화) / 주의(몬스터 수 증가) / 안전(보상·유지) / 선택형.
  독립 적대검증에서 오분류 5건이 나와 고쳤다. 정규식 기반이라 **패치마다 stat id 가 바뀌면 조용히 틀린다** — 앱에서는 분류 결과를 픽스처로 고정하고 회귀 테스트가 필요.
- **초반 경로** (`hc_opt.py`): 목표 11개(에센스·성소·서판·경로석 유지 등)를 순서 1,500가지로 돌려 위험 최소 → 58pt · 위험 3. 수학적 최소 증명은 없다.
- **나머지 순서** (`full_order.py`): 프런티어에서 안전 → 선택형 → 주의 → 위험, 막혔을 때만 위험을 먼저 뚫음.
- 알려진 구멍: 노드별 "70·75레벨 이상 지역 적용" 조건이 데이터에 없음 · 총 포인트가 문서마다 311(0.5.0~0.5.4) vs 화면 336(0.5.5) 불일치(미확인).
