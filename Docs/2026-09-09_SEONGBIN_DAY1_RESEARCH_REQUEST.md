## 대상과 범위

- 아래 영상 ID와 캐시를 이용해 **제작자 채널, 리그·패치, 캐릭터, 해당 육성의 첫 방송 날짜**를 실제 영상 메타데이터로 먼저 확인한다. 사용자에게서 새 링크나 정정이 오면 그것을 우선한다. 기존 후보들과 맞지 않아 대상이 불분명하면 후보와 이유를 짧게 제시하고 정확한 링크를 요청한다.

- 첫날에는 액트 시작, 초반 생존, 스킬과 보조젬 획득, 무기 강화, 퀘스트 선택, 전환 준비를 특히 자세히 본다. 후반 완성 세팅을 초반 필수 조건으로 앞당기지 않는다.
- Skadoosh 빌드가 임성빈 빌드와 같다고 가정하지 않는다. 빌드 비교가 필요하면 실제 공통점과 차이만 근거와 함께 쓴다.

## 영상 확인 방식

1. 관련 라이브의 제목·영상 ID·URL·방송 시작 시각·길이·날짜·패치·캐릭터·시작/종료 레벨을 목록으로 만든다. 업로드 날짜와 실제 라이브 날짜를 혼동하지 않는다. 첫날 또는 중간 방송이 없으면 누락으로 남긴다.
2. 공개 자막/음성으로 전체 내용의 시간 색인을 만든다. 기존 캐시를 우선 재사용하고, 자막이 없거나 오인식이 심한 핵심 구간은 음성 재인식 또는 직접 청취로 보완한다. 자동 인식임을 표시한다.
3. **설명하는 대목은 앞뒤 문맥과 실제 실행까지** 확인한다. 말하기만 하고 실행하지 않은 계획, 시험했다가 되돌린 세팅, 최종 채택을 분리한다.
4. **말이 없는 장비·젬·패시브·상점·거래·제작 화면도 찾는다.** 자막 키워드에만 의존하지 말고 화면 탐색으로 메뉴 전환을 찾은 뒤 해당 부분을 좁혀 본다. 가격·옵션·소켓·장착 전후·확정 버튼이 필요한 장면은 1~3초 간격 또는 연속 구간으로 확인한다.
5. 전투는 단계마다 일반 몬스터·희귀 몬스터·보스의 대표 장면을 실제로 본다. 스킬바만 보고 사용 순서를 만들어내지 않는다. 무기 세트 표시, 시전 동작, 버프, 토템, 생명력·마나·정신력 변화를 대조한다.
6. 모든 중요한 결론에 **영상 ID + 타임스탬프 URL + 읽은 화면/발언**을 붙인다. 서로 다른 영상의 같은 `00:40:00`을 섞지 않는다. 캡처를 만들었어도 직접 읽지 않았으면 확인한 것으로 세지 않는다.
7. 결과를 `발언 확인 / 화면 실행 확인 / 공개 데이터 대조 / 추정 / 미확인`으로 구분한다. 방송 발언은 그 사람이 그렇게 말했다는 근거이며, 게임 메커닉의 참을 자동으로 보장하지 않는다. 당시 패치와 현재 자료가 다르면 명시한다.
8. “전체 라이브를 다 봤다”, “빈 부분이 없다”는 표현은 실제 확인 범위가 뒷받침할 때만 쓴다. 화면·자막·음성의 확인 범위를 별도로 기록한다.

## 반드시 채울 내용

### 단계별 스킬·로테이션

- 액트/레벨/전직 단계별 주력 스킬, 보조젬 이름과 등급·개수, 얻는 곳과 장착 시점.
- 새 스킬을 배우면 **무엇을 빼고, 보조젬을 어디에서 어디로 옮기는지**. 인벤토리 소지만 한 젬을 장착으로 적지 않는다.
- 보조젬이 실제로 부족한 시점에는 우선순위와 대체 연결. 플래너 완성본의 여러 고등급 젬을 초반부터 요구하지 않는다.
- 빌드 전환의 실제 조건: 레벨, 전직, 스킬/보조, 정신력, 요구 능력치, 무기·고유 아이템, 재분배 골드, 회복과 비용. 전직 완료 하나만으로 즉시 전환한다고 단정하지 않는다.
- 무리 사냥/희귀/보스별 사용 흐름. 선행 조건, 버프 유지, 재설치·재시전 시점, 후딜·이동·회피를 구분한다. 고정 순서가 아니면 상황별로 쓴다.
- 무기 세트 I/II의 장비, 스킬 지정, 세트 전용 패시브, 전환 조건, 복귀 행동, 양쪽 저항·정신력·유지 가능한 버프. 해당 빌드에 없는 토템·함성을 억지로 넣지 않는다.

### 초반 생존과 장비 선택

- 초반 부위별 베이스/생명력/ES/방어도/저항/이속/재생/플라스크 선택과 실제 우선순위.
- 고정 수치와 % 증가, 방어와 딜의 교체 손익. 얻는 옵션뿐 아니라 잃는 생명력·재생·저항·정신력도 비교한다.
- 생명력·마나 비용과 회복 수단이 언제 생기는지, 실제 부족할 때 어떻게 하는지. 보호막·피해 흡수·방어 수치를 회복과 혼동하지 않는다.
- 사망/위험 장면의 원인, 좁은 길·금고·의식 등 선택적 위험을 감수한 이유, 회피할 수 있었던 조건. 특정 생명력 수치를 보편적인 생존 보장으로 적지 않는다.
- 퀘스트 영구 보상, 선택지, 추가 보스, 스킬/보조/정신력 젬 획득과 누락 시 영향.

### 거래·제작·주얼·목걸이

- 상점/거래소 검색 조건을 정확히 기록하고, 필터를 고치는 중간 화면과 최종 활성 조건을 구분한다.
- 후보 비교 → 선택 이유 → 실제 구매/획득 → 제작 → 장착을 연결한다. 구경만 한 매물을 샀다고 적지 않는다.
- 당시 가격·수량·화폐, 소지 재료를 꺼낸 것과 새로 산 것, 매각으로 마련한 자금을 구분한다. 당시 HC 가격을 현재 SC 시세로 안내하지 않는다.
- 주얼·목걸이·무기 등에서 원하는 옵션, 빈 접두/접미, 룬/소울 코어, 에센스/징조/훼손/성유 부여의 실제 순서와 결과.
- 제작 실패 옵션을 필수 목표로 복사하지 않는다. 성유 재료는 **등급·개수·배치 순서와 결과 미리보기/완료**까지 확인한다.
- 필요한 검색 정규식은 실제 게임 언어의 옵션 문구를 확인한 뒤 짧게 만든다. 게임에서 시험하지 않았으면 검증 완료라고 쓰지 않는다.

### 플래너 대조

- 제작자 가이드/Notes/단계 플래너와 실제 방송을 대조하고, 각 불일치의 의미를 설명한다.
- 실제 행동이 가이드와 다르면 시험·임시 대체·최종 변경 중 무엇인지 추적한다.
- 근거가 충분한 차이는 **임성빈 전용 새 출력 폴더의 플래너 사본**에 반영하고 변경표를 만든다. 원본 .build, 기존 사용자 설치본, Skadoosh 플래너는 덮어쓰지 않는다. 설치 요청은 이번 범위에 없다.

- 필요하면 `planner/`에 검증한 임성빈 전용 사본과 변경 내역. 필터 제작·설치나 Skadoosh 원본 변경은 하지 않는다.
- `CHECKPOINT.md`: 완료 범위, 다음 확인 위치, 파일 경로, 진행 중 작업, 미확인 항목. 컨텍스트가 압축되어도 이어갈 수 있게 갱신한다.

먼저 대상과 방송 순서를 확인한 뒤 첫날을 구체적으로 완결하고, 다음 날로 이어가며 차이를 누적해라. 자료 수집 계획만 적고 멈추지 않는다. 접근 불가·영상 누락은 정확히 남기고 확인 가능한 구간은 계속한다. 출처나 목표가 불분명해 사용자 입력이 반드시 필요할 때만 해당 의존 작업을 멈춘다.

현재 사용자 캐릭터 HCFB_CCTBurger는 하드코어에서 사망했다. 이후 SC 플레이를 말했고 HC 재시작은 고민 단계였다. 이 조사로 사용자의 캐릭터·플래너를 이미 전환했다고 가정하지 않는다.

## 환경과 작업 경계

- 사용자와 다른 세션이 같은 저장소를 쓰고 있다. 관련 없는 파일, 기존 브라우저 재생, 다른 세션의 프로세스는 조작하지 않는다. 프로세스 이름/와일드카드 종료, 런타임 직접 종료, 컴퓨터 종료 금지.
- 유튜브 공개 페이지와 공개 자막·영상을 사용한다. 로그인/비공개 자료가 꼭 필요하면 접근 제한을 우회하지 말고 상태를 보고한다.
- 브라우저 자동화는 자기 세션의 별도 컨텍스트에서 수행한다. Playwright MCP를 썼다면 실제 MCP 도구를 호출한 경우에만 그렇게 보고한다. 다른 도구를 썼으면 실제 도구명을 쓴다.
- 이미 설치된 Python 도구·자막·미디어 캐시와 기존 보조 스크립트를 우선 재사용한다. 긴 영상 전부를 고화질로 중복 다운로드하는 대신 필요한 구간을 확보한다.
- 한글 파일 출력은 UTF-8을 명시한다. 이미지 캡처·재생 구간의 원본 시간 오프셋을 검증한다.
- 사용자에게 진행 상황을 짧게 알려주고, 완료 보고에는 실제 확인/작성/검증한 것과 남은 미확인을 구분한다. 확실하지 않은 내용을 채우기 위해 다른 빌드나 옛 패치의 지식을 섞지 않는다.
