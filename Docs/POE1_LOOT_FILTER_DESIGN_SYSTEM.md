# POE1 전리품 필터 제작 기준서

> 상태: 필터를 새로 만들거나 수정할 때 먼저 읽는 정본
>
> 작성일: 2026-08-18
>
> 대상: POE1, SSF 및 빌드 전용 필터

## 1. 이 문서가 해결하는 문제

필터를 항목마다 즉흥적으로 칠하면 링크, 희귀도, 화폐, 젬, 퀘스트 아이템이 서로 구분되지 않거나 화면이 무지개처럼 보인다. 반대로 메인 컬러 하나만 모든 항목에 그대로 적용하면 가치와 종류를 구분할 수 없다.

따라서 앞으로 필터는 아래 다섯 층을 분리한다.

1. **아이템 논리**: 무엇을 잡고 어떤 순서로 판정하는가
2. **SSF/빌드 오버라이드**: 필수 장비, 제작 베이스, 파밍 자원
3. **엄격도**: 무엇을 Show/Hide 하는가
4. **시각 토큰**: 색, 글자 크기, 광선, 미니맵 모양
5. **소리 토큰**: 가치와 행동을 알리는 음성/효과음

색상이나 소리를 바꾸는 작업이 Show/Hide 조건을 바꾸면 안 된다. 엄격도를 바꾸는 작업이 필수 SSF 아이템의 모양이나 소리를 바꾸면 안 된다.

### 핵심 관찰

- 정상적인 FilterBlade 스타일도 모든 항목을 한 색으로 만들지 않는다.
- 대부분의 일반 스타일에서 6링크는 흰 글씨·흰 테두리·붉은 배경, 5링크는 시안 테두리, 4링크는 파란 테두리라는 안전 문법을 유지한다.
- 테마는 주로 **가치 티어의 배경 계단**, **중립 배경**, **글자 크기**, 일부 카테고리 강조를 바꾼다.
- 아이템 종류는 색 하나가 아니라 글씨, 테두리, 배경, 크기, 소리, 광선, 미니맵 모양을 함께 써서 구분한다.
- 따라서 “한 색상 계열의 밝기만 바꾸기”도, “카테고리마다 완전히 다른 원색을 배정하기”도 정답이 아니다.

### 제작 전에 사용자가 고를 출력 방식

단일판과 3단계판 중 어느 하나를 제작자가 임의로 기본값으로 정하지 않는다. 필터를 만들기 전에 반드시 사용자에게 다음 두 방식 중 하나를 고르게 한다.

#### A. 간편한 단일 진행형

- 출력: `*_SSF_Progressive.filter` 한 개
- 대상: 필터를 교체하기 귀찮거나 가볍게 플레이하는 사용자
- AreaLevel, ItemLevel, StackSize 같은 게임 상태로 캠페인과 맵 구간의 표시 강도를 자동 조절한다.
- 빌드 필수품과 SSF 진행 자원은 항상 표시한다.
- 장점: 처음부터 끝까지 파일을 바꿀 필요가 없다.
- 한계: 필터는 사용자의 창고 보유량이나 실제 빌드 완성도를 알 수 없으므로 개인 진행도에 완벽히 맞출 수는 없다.

#### B. 1 / 3 / 5 수동 전환형

- 출력 1: `*_SSF_1_Regular.filter` — 리그 시작, 캠페인, 초기 아틀라스
- 출력 2: `*_SSF_3_Strict.filter` — 노란/빨간 맵과 일반 파밍
- 출력 3: `*_SSF_5_Uber_Strict.filter` — 빌드가 갖춰진 고밀도 엔드게임
- 대상: 진행 상황과 파밍 밀도에 맞춰 직접 엄격도를 바꾸려는 사용자
- 장점: 각 단계에서 화면 정리 수준을 정확히 통제할 수 있다.
- 한계: 사용자가 적절한 시점에 필터를 직접 바꿔야 한다.

어느 방식을 고르더라도 정본은 하나만 유지한다. 필수 장비, SSF 제작 자원, 메인 컬러 토큰, 아이콘과 핵심 소리는 동일하고 표시 범위와 저가치 알림만 달라진다.

## 5. Sanavi에서 가져올 것과 가져오지 않을 것

Sanavi 1-Regular는 58종의 커스텀 사운드 파일을 참조하며, 로컬 게임 폴더에 58종이 모두 존재한다. 게임 폴더 전체에는 MP3 147개가 있다.

대표적인 Sanavi 행동 사운드는 다음과 같다.

- 5링크: `5Link.mp3`
- 일반 6링크 계열: `6Link.mp3`
- 필수/귀중 고유: `MyPrecious.mp3`
- 고가 화폐: `Thatsworthsomething.mp3`, `Cha-Ching.mp3`, `HolyShit.mp3`
- 일반적으로 확인할 드롭: `ProbPickUp.mp3`
- 젬/카드/스카라브/플라스크: 종류별 전용 음성

가져올 것은 **소리의 행동 의미와 가치 계층**이다. Crimson의 빨간 배경을 모든 가치 티어에 그대로 복사하지 않는다. 같은 아이템에 내장 사운드와 커스텀 사운드를 중복 호출하지 않으며, 엄격한 필터일수록 저가치 소리부터 제거한다.

## 6. 메인 컬러 기반 생성 규칙

사용자는 최종적으로 메인 컬러 하나만 고른다. 구현은 그 RGB를 HSL 또는 OKLCH로 변환해 아래 토큰을 만든 뒤 다시 POE용 RGB로 출력한다. 규칙마다 RGB를 직접 쓰지 않는다.

### 6.1 팔레트 토큰

`P`는 사용자가 고른 메인 컬러다.

| 토큰 | 생성 원리 | 용도 |
|---|---|---|
| `P-950` | P를 검정과 약 82% 혼합 | 거의 검은 공통 배경 |
| `P-900` | 검정 70% 혼합 | 일반 카테고리 배경 |
| `P-700` | 검정 45% 혼합 | 중간 가치 배경 |
| `P-500` | 원래 메인 컬러 | 강한 테두리/중요 배경 |
| `P-300` | 흰색 30% 혼합 | 밝은 테두리/글씨 |
| `P-100` | 흰색 72% 혼합 | 최고 대비 글씨 |
| `A-warm` | P의 색상각을 20~30도만 이동 | 화폐/제작의 제한된 보조 강조 |
| `A-cool` | P의 반대색이 아니라 20~30도 반대 방향 이동 | 젬/특수 베이스의 제한된 보조 강조 |
| `N-950/700/300/50` | 중립 회색 | 하위 티어와 흰 글씨 |

전체 화면의 약 70%는 `P` 계열, 20%는 중립색, 10% 이하만 보조색과 의미 고정색을 사용한다. `A-warm`과 `A-cool`은 모두 쓰지 않고 필요한 경우 하나만 고르는 것을 기본으로 한다.

### 6.2 의미가 고정된 예외

아래는 메인 컬러보다 안전성과 즉시 인지가 우선한다.

- **빌드 필수 고유**: 흰 글씨, 흰 테두리, 붉은 배경
- **6링크**: 흰 글씨, 흰 테두리, 붉은 배경, 가장 큰 글자와 아이콘
- **퀘스트 아이템**: 사용자가 지정한 어두운 초록 계열. 전용 퀘스트 소리, 초록색 임시 광선, 초록색 원 아이콘을 사용한다.
- **Dead Man's Sulphur**: 검녹 배경과 산성 연두 테두리
- **미분류 신규 아이템 안전망**: 분홍/마젠타 경고색
- **타락·미러 위험 표식**: 붉은 테두리

이 예외들의 배경은 어둡게 유지하고, 동시에 화면에 여러 개가 떠도 원색 덩어리처럼 보이지 않게 한다.

### 6.3 가치 단계

| 가치 | 글씨 | 테두리 | 배경 | 알림 |
|---|---|---|---|---|
| S 필수/안전 | 흰색 | 흰색 | 의미 고정색 | 45, 전용 소리, 영구 광선, 아이콘 0 |
| A 최우선 | 흰색 또는 `P-100` | `P-100` | `P-500` | 45, 강한 소리, 영구 광선, 아이콘 0 |
| B 중요 | `P-100` | `P-300` | `P-700` | 42~45, 보통 소리, 임시 광선, 아이콘 1 |
| C 수집/제작 | `P-300` | `P-500` | `P-900` | 38~42, 조용한 소리 또는 무음, 아이콘 2 |
| D 정보성 | `N-300` | `P-700` 또는 중립 | `P-950` | 32~38, 무음, 광선 없음 |
| Hide | 어두운 중립 | 투명/어두운 중립 | 투명에 가까운 배경 | 18, 모든 알림 제거 |

밝기 대비가 부족하면 흰색/검정 글씨를 자동 선택한다. 색각만으로 가치를 표시하지 않는다.

## 7. 항목별 시각 문법

### 링크와 희귀도

링크 수는 테두리 강도, 배경 면적감, 글자 크기, 소리, 광선, 아이콘 크기로 구분한다. 희귀도는 글씨색으로 보조한다.

| 항목 | 크기 | 핵심 표현 |
|---|---:|---|
| 3링크 | 35~36 | 중립/어두운 배경, 얇은 `P-700`, 무음 또는 임시 효과, 아이콘 2 |
| 4링크 | 40 | `P-300` 테두리, `P-900` 배경, 임시 효과, 아이콘 2 |
| 5링크 | 45 | `P-100` 테두리와 `P-700` 배경, 전용 소리, 영구 효과, 아이콘 1 |
| 6링크 | 45 | 흰 테두리·붉은 배경, `6Link.mp3`, 영구 Red, 아이콘 0 |

희귀도 글씨는 Normal=흰색, Magic=밝고 저채도인 청색/`A-cool`, Rare=밝은 금색을 유지할 수 있다. 단, 링크 수의 구분을 이 세 색에만 맡기지 않는다.

### 카테고리와 미니맵 모양

색을 늘리지 않고 모양을 고정해 학습 비용을 낮춘다.

| 카테고리 | 모양 |
|---|---|
| 고유/필수품 | Star |
| 일반 화폐 | Circle 또는 Cross 중 하나로 통일 |
| 젬 | Triangle |
| 링크/제작 베이스 | Diamond |
| 지도 | Square |
| 점술 카드 | Square (지도와 공유. 카드는 가치 티어 색과 글자 크기로 구분한다) |
| 조각/스카라브 | Hexagon 또는 Kite |
| 퀘스트 | Circle (Green) |
| 플라스크 | Raindrop |
| 미분류 안전망 | UpsideDownHouse |

광선색은 POE가 지원하는 제한된 색 중 메인 컬러에 가장 가까운 하나를 테마 전체에서 사용한다. Red는 필수/위험, White는 최고 가치 안전 표시용으로 예약한다.

### 기본 화폐

- 지혜/포탈은 둘 다 크게 보이되 같은 소리를 쓰지 않는다.
- 캠페인과 SSF 초반에는 40~45, 후반 엄격도에서는 스택 수 조건을 사용해 알림을 낮춘다.
- 지혜와 포탈은 같은 핑크 화폐색으로 뭉개지지 않게 글씨/테두리 명도와 소리를 분리한다.
- 기본 제작 화폐는 낱개, 3개 이상, 6개 이상을 가치 토큰 C/B/A로 승급한다.

### 젬

- 모든 젬은 같은 카테고리 모양인 Triangle을 쓴다.
- 일반 레벨링 젬은 어두운 배경과 조용한 테두리만 사용한다.
- 품질, 20/20+, 21레벨, Vaal, 변형, 각성, Empower/Enhance/Enlighten은 가치 단계에 따라 승급한다.
- 젬이라는 이유만으로 모든 젬에 큰 소리와 영구 광선을 주지 않는다.

## 9. 한 정본에서 선택한 출력 방식을 만드는 구조

정본은 아래 데이터를 한 번만 가진다.

```text
build targets + SSF targets
            |
            +-- visual tokens(main colour)
            +-- sound tokens(Sanavi-derived)
            +-- strictness policy
                    +-- A: Progressive 한 개
                    |
                    +-- B: 1 Regular
                            3 Strict
                            5 Uber Strict
```

규칙 순서는 다음과 같이 고정한다.

1. 6링크 및 안전 규칙
2. 빌드 필수 고유/필수 재료
3. 현재 NeverSink 경제 티어의 T0/T1 고유 베이스·화폐
4. SSF 진행 및 제작 타깃
5. 링크·젬·화폐의 단계별 오버라이드
6. 선택한 NeverSink/SSF 일반 규칙
7. 엄격도별 Hide 층
8. 미분류 신규 아이템 안전망

필수 규칙은 선택한 모든 출력에서 마지막 Hide보다 먼저 확정되는 terminal `Show`여야 한다. 단, 의도적으로 장식을 겹치는 규칙만 `Continue`를 사용한다.

NeverSink 계열을 따른다고 명시한 필터는 테마 색만 참고해서는 안 된다. 생성 시점의 공식 NeverSink 필터에서 최상위 고유 베이스와 화폐 경제 티어를 다시 가져와 별도 terminal `Show`로 둔다. 이 규칙들은 일반 고유/일반 화폐 데코레이터보다 먼저 평가되어야 하며, 리그 경제가 바뀌면 목록도 다시 갱신한다. 빌드 필수품과 시장 T0가 겹치면 빌드 필수 시각 문법을 우선하되 둘 다 최상위 가시성과 알림 강도를 유지한다.

### Wrecker SSF 원본을 사용하는 경우

`C:\Users\User\Desktop\SSF.txt`를 입력으로 받는 조합은 NeverSink 완성본을 본체로 삼지 않는다. 이 파일의 AreaLevel 기반 Hide 진행, 장비 베이스 선별, 비장비 SSF 수집 정책이 **표시 논리의 정본**이다. `death oath.txt`와 `allie.txt` 같은 NeverSink/FilterBlade 출력에서는 조건과 시각 지시어를 추출하되, 해당 규칙을 `Continue` 장식 레이어로 변환해 SSF의 최종 Show/Hide 결정을 바꾸지 않게 한다.

고정 합성 순서는 다음과 같다.

1. NeverSink 광범위 시각 `Continue` 레이어
2. NeverSink 고가치 강조 `Continue` 레이어
3. 빌드 필수품과 최신 경제 T0 terminal `Show`
4. 활성 색상 지시어를 제거한 Wrecker SSF 진행/표시 정본

즉, 이 조합에서 NeverSink는 분류·가치 표현을 제공하고 Wrecker SSF는 실제 가시성과 진행형 엄격도를 결정한다. NeverSink의 terminal Show/Hide 전체를 뒤에 붙이면 SSF 정책이 바뀌므로 금지한다. 원본에 현대 POE1에서 제거된 조건이 남아 있으면 원본은 보존하고 생성 단계의 명시적 호환성 패치로만 제외한다.

### 규칙 누락을 판정하는 절차

화면에서 평범하게 보인다는 이유만으로 해당 범주의 규칙이 없다고 단정하지 않는다. 반드시 최종 `.filter`와 입력 원본을 모두 검색하고 다음 셋을 구분한다.

1. 규칙이 실제로 없음
2. 규칙은 있지만 조건 범위가 좁아 fallback만 적용됨
3. 규칙은 매칭되지만 뒤의 `Continue` 규칙이 표현을 다시 덮어씀

Wrecker+NeverSink 조합의 일반 장비가 대표 사례다. 일반 무기용 소켓/DropLevel 진행 규칙과 알려진 장비 전체 fallback은 이미 존재하지만, 3소켓 미만의 비특수 일반 무기는 회색 공통 fallback에만 걸릴 수 있다. 이때 해결은 기존 진행 규칙을 중복 생성하는 것이 아니라, 알려진 장비 fallback 직후에 장비 클래스 한정 Normal/Magic/Rare 기본 표현을 넣고 이후 구체 규칙이 덮어쓰게 하는 것이다.

블록 수와 중복 지시어를 셀 때 `Show `처럼 뒤 공백이 붙은 원본도 포함해야 한다. 블록 시작 정규식은 `^(Show|Hide)(?:\s+#.*)?\s*$`로 고정한다. 더 엄격한 정규식으로 얻은 과거 Show/Hide 통계는 신뢰하지 않는다.

1. 이 문서와 대상 빌드 가이드를 읽는다.

## 11. 빌드 입력과 앱의 수동 추가 흐름

### 11.1 빌드에서 자동으로 가져오기

사용자가 PoB, 빌드 가이드 또는 빌드 문서를 주면 다음 순서로 필터 타깃 후보를 만든다.

1. PoB `Notes`와 가이드에서 `필수`, `코어`, `우선`, `파밍`, `제작`, `업그레이드`, `선택` 표현을 찾는다.
2. PoB의 장비·젬·플라스크 구조 데이터와 대조해 정확한 아이템 이름과 단계 정보를 보완한다.
3. 단순히 현재 장착했다는 이유만으로 모든 장비를 필수품으로 확정하지 않는다.
4. 자동 추출 결과를 `필수`, `중요`, `제작용`, `선택`, `확인 필요`로 나누어 사용자에게 보여준다.
5. 사용자가 승인한 항목만 필터 정본의 build target에 저장한다.

노트가 충분하면 필수 장비와 진행 목표를 자동 구성한다. 노트가 없거나 애매하면 추측해서 최우선 알림으로 넣지 않고, 구조 데이터에서 찾은 후보를 보여주거나 수동 추가로 넘긴다.

### 11.2 앱에서 아이템 이름으로 추가하기

앱에는 다음 흐름을 제공한다.

```text
필터 수정
  -> 아이템 추가
  -> 한글 또는 영문 유니크 이름 검색
  -> 원하는 유니크 선택
  -> 우선순위 선택(필수/중요/제작/선택)
  -> 적용 대상 선택(단일판 또는 선택한 1/3/5 전부)
  -> 미리보기
  -> 정본 저장 및 필터 재생성
```

사용자는 유니크 이름만 알면 된다. `카옴의 심장`과 `Kaom's Heart` 중 어느 쪽으로 입력해도 같은 항목을 찾아야 한다. 검색 결과는 `카옴의 심장 (Kaom's Heart)`처럼 공식 한글명과 영문명을 함께 표시한다.

앱은 POE1 공식 한글 데이터와 영문 데이터를 같은 안정적인 아이템 ID에 연결해 양방향 자동완성을 제공한다. 한글 이름을 임의 번역해서 만들지 않는다. 검색어의 공백·대소문자는 무시하고, 부분 검색과 제한적인 오타 교정도 지원한다. 실제 필터에 필요한 영문 BaseType 변환은 선택 후 내부에서 자동 처리한다. BaseType을 사용자가 직접 찾거나 입력하게 하지 않는다. POE2 아이템이나 현재 패치에서 존재하지 않는 이름은 저장 전에 차단한다.

예시:

| 사용자 입력 | 검색 결과 | 내부 저장/생성 |
|---|---|---|
| `카옴` | `카옴의 심장 (Kaom's Heart)` | 안정적 아이템 ID + 영문 BaseType |
| `Kaom` | `카옴의 심장 (Kaom's Heart)` | 위와 동일한 ID |
| `닉타` | `닉타의 등불 (Nycta's Lantern)` | 안정적 아이템 ID + `Crystal Sceptre` |

### 11.3 이름을 필터 조건으로 변환하는 규칙

| 입력 종류 | 생성할 조건 | 주의점 |
|---|---|---|
| 일반/마법/희귀 베이스 | 정확한 `BaseType ==` + 필요시 Rarity/ItemLevel | 제작 목적에 맞는 아이템 레벨을 함께 받는다. |
| 고유 아이템 이름 | 앱이 POE1 데이터에서 베이스 타입으로 자동 해석한 뒤 `Rarity Unique` + `BaseType ==` | 사용자는 이름만 입력한다. 같은 베이스의 다른 고유도 함께 표시되는 경우에만 앱에서 짧게 안내한다. |
| 화폐/조각/에센스 | 정확한 `BaseType ==` | 스택 수에 따라 알림 단계를 올릴 수 있다. |
| 젬 | 정확한 BaseType, Class, Quality, GemLevel, Transfigured 조건 | 일반/변형/각성/Vaal 이름을 구분한다. |
| 지도 | BaseType/Class + 필요시 MapTier | 파밍 지도와 단순 고티어 지도를 구분한다. |
| 장비군 | Class/BaseType 목록 + ItemLevel/Influence | 너무 넓은 규칙이 되면 예상 드롭 수를 경고한다. |

고유 이름을 베이스 타입으로 바꿀 때 같은 베이스에 여러 고유가 있으면 다음처럼 표시한다.

> `Nycta's Lantern`을 추가하면 드롭 필터는 `Crystal Sceptre` 고유 베이스를 표시합니다. 같은 베이스를 공유하는 다른 고유 아이템도 표시될 수 있습니다.

### 11.4 저장 방식

앱이 완성된 `.filter`의 임의 위치에 문자열을 직접 덧붙이면 안 된다. 사용자가 추가한 항목은 별도의 정본 데이터에 안정적인 ID로 저장하고, 그 정본으로 선택한 출력 전체를 다시 생성한다.

권장 개념 구조:

```json
{
  "id": "build.core.unique.nyctas_lantern",
  "display_name": "Nycta's Lantern",
  "resolved_base_types": ["Crystal Sceptre"],
  "rarity": "Unique",
  "priority": "required",
  "source": "user_manual",
  "apply_to": "all_outputs",
  "ambiguity_warning": true
}
```

이 구조를 사용하면 항목 추가·수정·삭제가 가능하고, 메인 컬러나 출력 방식을 나중에 바꿔도 사용자가 추가한 아이템이 사라지지 않는다.

- **출력 방식**: 사용자가 단일 진행형 1개 또는 1/3/5 전환형 3개 중 선택
- **시각 구조**: FilterBlade Default·Alloy·Cobalt의 다중 채널 문법
- **메인 컬러**: 사용자가 한 색만 선택하면 파생 토큰 생성
- **소리**: Sanavi의 행동/가치 계층을 정리해 사용
- **고정 예외**: 필수 고유, 6링크, 퀘스트, Dead Man's Sulphur, 미분류 안전망
- **빌드 입력**: Notes/가이드에서 후보 자동 추출 후 사용자 승인
- **누락 보완**: 앱의 필터 수정에서 이름 검색 후 정본에 추가하고 전체 출력 재생성

출력 방식과 메인 컬러가 정해지기 전에는 실제 필터 RGB를 다시 손대지 않는다.
